# 商务工作台长期目标与范围锁定

> 生效日期：2026-07-19  
> 状态：唯一产品主线  
> 适用仓库：BSAIGC_DESKTOP

## 1. 唯一产品目标

把本仓库交付为一套独立的 Windows 桌面“商务工作台”，面向客户经理和商务岗位完成以下闭环：

```text
客户/项目
→ 需求与资料
→ AI识别和缺口追问
→ 报价
→ 合同生成、审查和版本
→ 付款计划与请款
→ 交付与验收
→ 到账与回款
→ 经营台账与归档
```

第一条必须先交付的纵向闭环：

```text
导入 PDF/DOCX 合同
→ 解析/OCR
→ Agent + 确定性规则审查
→ Evidence 原文定位
→ 人工确认/驳回
→ 生成审查报告
→ Vault 保存和任务恢复
```

## 2. 产品形态

- 只提供商务工作台，不继续扩展创意中心、无限画布、摄影执行、案例素材库或分秒针模块。
- UI 和核心交互采用 Codex Desktop 的面板式工作方式作为设计参考：左侧工作区/任务，中间 Agent 主工作区，右侧上下文与 Artifact，底部输入与运行状态。
- 只复用交互结构和工作模式，不复制 OpenAI 品牌、图标、文案或专有资产。
- 页面必须通过 Client SDK 使用后端能力，禁止 React 直接调用 Tauri IPC、Provider、Codex、R2 或本地绝对路径。
- 视觉尚未确认前，以可替换的中性商务视觉实现功能，不建立第二套页面业务状态。

## 3. 存储与同步范围

存储架构：

- SQLite Task Ledger 是任务和业务记录权威。
- Local Vault 是合同、模板、报告和附件的主存储与显示权威。
- 所有导入和生成结果必须先完整写入 Local Vault，校验成功后才返回稳定 `assetId`。
- Cloudflare R2 是线上异步备份副本，不是业务数据库、任务权威或成功判定来源。
- 本地保存成功即可完成用户任务；断网、Worker或R2故障不得阻断合同审查、文档生成和本地查看。
- 后端通过 Durable Backup Outbox 排队上传R2，支持重试、取消、校验、去重、断点恢复和可见备份状态。
- 前端和React不得持有R2密钥；上传凭据、签名或Worker通信只能由Rust Host的Backup Adapter处理。
- 线上恢复必须验证对象哈希、manifest、项目权限和版本，恢复结果先落回 Local Vault 再对UI可见。
- 团队同步、D1业务镜像和跨设备协作不在当前范围；R2仅承担灾备和恢复。

## 4. 暂停和隐藏范围

以下范围默认暂停，不得自行启动：

- 创意中心。
- 无限画布。
- 正式网页版。
- 销帮帮、飞书和其他外部业务系统同步。
- 电子签章平台。
- D1业务镜像、团队同步和跨设备协作；R2只承担异步备份和恢复。
- 与商务工作台无关的图片、视频、音频生成页面。

现有无关代码处理原则：

1. 第一阶段从导航和默认入口隐藏，不继续扩展；
2. 不在未做依赖审计前直接删除，避免破坏通用 Task、Asset、Memory、Security 和Codex Host；
3. 商务闭环稳定后，再按“无引用、无共享协议、无迁移依赖、测试通过”四项条件分批清理；
4. 禁止以“顺手重构”为理由改动无关模块。

## 5. 开源复用原则

- 官方 Codex app-server 是唯一 Agent Runtime。
- 优先直接依赖成熟 MIT/Apache/BSD 项目，其次使用隔离 sidecar，再其次选择性复用；只有商务胶水和统一 adapter 自研。
- 当前PoC主线：Docling、PaddleOCR、RapidOCR、LiteParse、PDF.js、Open XML SDK、Open-Xml-PowerTools、ClosedXML、MiniWord、assistant-ui、TanStack Table、RJSF、GoRules Zen。
- 大型ERP/CRM只借领域模型和异常状态，不引入第二套业务数据库、权限、审批、任务或Agent Runtime。

## 6. 防跑偏检查

每次开始新任务前必须回答：

1. 是否直接推进商务闭环？
2. 是否能形成用户可见结果？
3. 是否复用了现有协议和成熟开源能力？
4. 是否误入创意中心、无限画布、云同步或纯地基建设？
5. 是否新增了第二套数据、任务、权限、审批或Agent权威？

若第1或第2项为“否”，或第4/5项为“是”，立即停止该支线并回到合同审查纵向闭环。
