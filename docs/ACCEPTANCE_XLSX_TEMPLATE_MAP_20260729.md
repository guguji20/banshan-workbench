# 合同结算单 XLSX 模板映射与回归基线

> 检查日期：2026-07-29  
> 检查方式：原件只读；Excel 16 COM 读取；OOXML 包结构核对；Excel 导出 PDF；Poppler 160 DPI 渲染；历史成品逐页视觉对照  
> 结论：该模板可以作为 `5 文件 6 类内容` 中“合同结算确认”的真实 XLSX 底稿，但必须采用“克隆模板后定点写值”的适配器，不能用当前通用 XLSX 生成器从零重建。

## 2. 工作簿结构

工作簿共 4 个工作表：

| 顺序 | 工作表 | 可见性 | Used range | 用途 |
|---:|---|---|---|---|
| 1 | `1-审批流` | 隐藏 | `C3:N5` | 审批路由说明，不属于交付页 |
| 2 | `附件1最终结算书` | 可见、当前活动页 | `B1:J34` | 唯一正式输出页 |
| 3 | `最终结算书-填报说明` | 可见 | `B1:O34` | 人工填报说明，不应进入客户交付 PDF |
| 4 | `审批要点建议` | 隐藏 | `B2:F14` | 审批提示，不属于交付页 |

只有一个已有命名范围：

```text
附件1最终结算书!Print_Area = 附件1最终结算书!$A$1:$I$34
```

当前原件没有语义命名单元格或命名表格。接入策略必须二选一：

1. 以“模板 SHA-256 + 工作表名 + 固定地址”绑定本文件；模板变化必须升版本并重新验图。
2. 在导入 Vault 后创建新的规范化模板版本，为映射单元格增加语义命名范围；不得回写或覆盖真实需求目录中的原件。

不得只按文件名匹配模板。

## 3. 正式输出页结构合同

### 3.1 页面与打印

| 项目 | 原件值 | 输出要求 |

| 纸张 | A4，`paperSize=9` | 必须保持 |
| 方向 | 纵向 | 必须保持 |
| 水平居中 | 是 | 必须保持 |
| 左/右边距 | 0.3937007874 inch，约 1 cm | 必须保持 |
| 上边距 | 0.7874015748 inch，约 2 cm | 必须保持 |
| 下边距 | 0.5905511811 inch，约 1.5 cm | 必须保持 |
| 页眉/页脚边距 | 0.3937007874 inch，约 1 cm | 必须保持 |

## 4. 机器可执行字段映射建议

### 4.1 当前数据缺口

现有 `BusinessDocumentSnapshot.profile` 能直接提供项目名、客户法定名称和供应方法定名称，但不能同时、明确、冻结以下结算字段：

- 合同名称
- 合同编号
- 原合同金额
- 合同额调整
- 质保金比例
- 最终结算金额及其人民币大写

历史成品同时出现“项目名称”和“合同名称”，不能把 `profile.projectTitle` 一值两用。验收文档快照应增加或关联一个冻结的 settlement/contract 数据块；不能在生成时临时从 UI 文案、OCR 当前结果或未冻结的报价单推断。

建议适配器输入：

```json
{
  "projectTitle": "string",
  "contractTitle": "string",
  "contractNumber": "string",
  "customerLegalName": "string",
  "supplierLegalName": "string",
  "originalContractAmountCents": "integer",
  "contractAdjustmentCents": "integer",
  "retentionRateBps": "integer|null",
  "finalSettlementAmountCents": "integer",
  "finalSettlementAmountUppercaseCny": "string"
}
```

金额仍以整数分存储。只有在写入 XLSX 时转换为人民币元数值，禁止用二进制浮点累计。

### 4.2 单元格映射

| 语义字段 | 目标 | 写入类型 | 规则 |
|---|---|---|---|
| `customerLegalName` | `B1`、`E9` | 字符串 | 两处写同一冻结值；`C29` 由公式引用 `E9` |
| `contractTitle` | `B2:I2` 的 `B2` | 字符串 | 红色，12 pt 华文细黑，保留换行/对齐；`E7` 由公式引用 `B2` |
| `projectTitle` | `E6` | 字符串 | 红色，10 pt 宋体 |
| `contractNumber` | `E8` | 字符串 | 必须按文本写入，保留连字符、括号和可能的前导零 |
| `supplierLegalName` | `E10` | 字符串 | 红色，10 pt 华文细黑；`G29` 由公式引用 `E10` |
| `originalContractAmountCents` | `H14` | 数值 | `cents / 100`；保留会计格式，零显示 `-` |
| `contractAdjustmentCents` | `H15` | 数值 | 净调整额：减账为负、加账为正、无调整为 0；不写 `F15/G15` |
| 保留项 | `H16` | 空白 | 公式范围包含该格，但模板未定义业务含义；1.0 不得擅自占用 |
| `retentionRateBps` | `E21` | 数值或空白 | `bps / 10000`；单元格格式 `0%`；无质保金时保持空白，不写字符串 `0%` |
| `finalSettlementAmountCents` | `H18` | 只校验 | 不覆盖公式；必须等于 `H14 + H15 + H16` |
| 质保金金额 | `H21` | 公式结果 | 不覆盖公式；必须等于 `H18 * E21`，空比例按 0 处理 |
| 结算确认句 | `C25:H25` 的 `C25` | 富文本 | 从 `H18` 的最终金额生成大写和小写金额，不读取模板示例文本 |
| 客户签章名称 | `C29` | 公式结果 | 不覆盖公式 |
| 供应方签章名称 | `G29` | 公式结果 | 不覆盖公式 |
| 客户签署日期 | 盖章后人工填写 | 不自动写 | 历史合格成品为空；保留 `Line 3` 和 `日期:` |
| 供应方签署日期 | 盖章后人工填写 | 不自动写 | 历史合格成品为空；保留 `Line 4` 和 `日期:` |

模板中的 `F13/G13/H13` 标题为“减帐/加帐/合计”，但 `F14:G16` 没有计算公式，填报说明只要求写 `H14/H15`，而 `H18` 只计算 `SUM(H14:H16)`。因此 1.0 必须把合同调整作为带符号净额写入 `H15`，不能自行发明 `F15/G15 -> H15` 公式。

### 4.3 必须保留的公式

```text
E7  = B2
H18 = SUM(H14:H16)
H21 = H18*E21
C29 = +E9
G29 = +E10
```

任何映射都不得用静态值覆盖这 5 个公式。若 OOXML 写入库不执行计算，必须同时做到：

1. 按整数分在 Host 侧重算期望结果。
2. 更新公式单元格缓存值，或使用 Excel/LibreOffice 完整重算后再保存。
3. 设置完整重算标记，保证下次打开不会显示旧缓存。
4. 生成后再次读取公式和显示值，不能只验证输入单元格。

### 4.4 `C25` 富文本模板

`C25:H25` 不是普通纯文本。固定句式为：

```text
兹特此同意确认上述合同最终结算书内所示之金额人民币：{人民币大写}（{小写金额}RMB元），按本合同结清所有应付款项,承包方放弃一切对发包方的索赔。承包方仍需按合同约定完成质保期的所有工作并承担相应责任（如有）。
```

富文本要求：

- `兹特此同意确认`：黑色，华文细黑 10 pt。
- `上述`：红色 `#FF0000`，华文细黑 10 pt。
- `合同最终结算书内所示之金额人民币：`：黑色，华文细黑 10 pt。
- `{人民币大写}（`、小写金额、`RMB`、`元）`：全部红色；中文使用华文细黑 10 pt，`RMB` 使用 Arial 10 pt。
- 其余固定条款：黑色，华文细黑 10 pt；固定英文逗号 `,` 使用 Arial 10 pt。
- 保持 `wrapText=true`、左对齐、垂直居中和第 25 行 43.5 行高。

模板“填报说明”示例本身存在金额不一致：`H18` 示例值为 `3,397,307.00`，而示例大写文本对应约 `3,398,197`。生成器不得复制该示例，必须从冻结的最终结算金额重新生成并做双向校验。

白鹅潭历史回归基线：

```text
H14 = 97,520.00
H15 = 0，显示为 -
H18 = 97,520.00
E21 = 空白
H21 = 0，显示为 -
人民币大写 = 玖万柒仟伍佰贰拾元整
C25 小写片段 = 97520RMB元
```

历史样本只证明了整元写法。最终金额含角分时，`C25` 的小写金额格式必须先取得业务确认；在规则固化前应阻断自动批准，而不是自行选择 `97520.50RMB元` 或舍入为整数。

## 5. 样式与视觉基线

### 5.1 颜色和字体

- 标题/正文主字体：华文细黑、宋体、Arial，按原单元格保留。
- 正文主字号：10 pt；页首公司和合同标题：12 pt。
- 输入/金额强调色：`#FF0000`。
- “承 包 方”标签色：`#333399`。
- 普通正文：`#000000`。
- 不得统一替换字体，不得把整页刷成红色或黑色。

关键样式：

```text

_ * #,##0.00_ ;_ * -#,##0.00_ ;_ * "-"??_ ;_ @_

H18:
#,##0.00;[红色]-#,##0.00

0%
```

## 7. 输出包保全与脱敏

原 XLSX 包含以下非业务元数据：

- `x15ac:absPath` 绝对本地路径。
- 原作者和最后修改者属性。
- 上次打印时间。

生成后的客户交付副本必须清理本地绝对路径和个人作者元数据，但不得改动真实原件。清理后要再次验证公式、打印区、图形、页脚和 PDF 版式。

原包无宏、无外部链接、无表格、无条件格式；正式生成后也不应新增宏或外部链接。目标页 drawing 没有外部图片关系，说明空白模板内没有真实公章图片。

## 9. 接入顺序

1. 在 Vault 注册原模板 Asset，记录精确 SHA-256，不把原件放进 Git。
2. 为 `contract-settlement` 输出规格冻结模板 key、源 SHA、格式和所需字段。
3. 扩充验收文档快照，冻结合同名称、合同编号和结算金额数据；不要只依赖 `BusinessProfile`。
4. 实现“克隆模板 -> 定点写值 -> 保留公式/样式 -> 重算 -> 移除提示椭圆 -> 清理元数据 -> 导出单一工作表”的适配器。
5. 先跑白鹅潭 `97,520` 基线，再覆盖负调整、正调整、质保金比例、长合同名和非整元金额。
6. XLSX 结构断言、公式断言和 PDF 视觉断言全部通过后，才允许把该输出规格标记为可批准、可生成。

## 10. 未决业务规则

- 最终金额含角分时，`C25` 小写金额的正式书写格式尚无真实合格样本。
- `H16` 被最终金额公式包含，但模板和填报说明没有定义其业务角色；1.0 保持空白。
- 模板中 `H20` 和 `H21` 都会显示质保区数值/横杠，填报说明只确认 `E21 -> H21` 公式链；不得擅自删除其中一行。
- 历史成品没有实际公章和签署日期，只证明了预留位置，不证明数字盖章方案。

这些未决项不影响白鹅潭整元、零调整、零质保金的回归，但必须在开放更广泛合同结算自动批准前固化。
