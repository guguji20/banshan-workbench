# 半山商务工作台业务版 1.0 总计划

> 状态：需求基线已确认，开发尚未开始
> 存档日期：2026-07-28
> 当前代码基线：1.3.0，本地存在待整理改动
> 目标：个人本地优先、共享成果可复用、以聊天驱动真实商务工作

## 1. 产品定义

半山商务工作台业务版 1.0 是一个以客户项目工作区为中心的桌面商务自动化工具。

产品采用 Codex 式聊天入口。用户可以添加本地文件夹、拖拽文件、粘贴截图，并通过自然语言独立启动报价、合同审查、验收、结算、归档和资料检索任务。

产品不是多个 AI 提示词页面，也不是要求所有事情按固定流程执行。报价和验收是两个独立的日常高频场景，可以共用同一套聊天界面、项目资料和模板，但任一场景都可以直接启动。

## 2. 核心原则

1. 本地优先：个人聊天、草稿、项目文件和业务数据库默认保存在本机。
2. 共享受控：只有被确认并获管理员授权的成果案例进入 R2 共享知识库。
3. 独立任务：报价、合同、验收、结算和发票可以分别启动并并行存在。
4. 项目复用：公司、客户、合同、模板、价格和历史成功件只配置一次，后续批次直接继承。
5. 确定性优先：金额、税率、数量、优惠、公式和状态流转由程序计算，不交给大模型猜测。
6. AI 辅助：AI 负责识别、分类、提取、归纳、匹配、风险提示和自然语言修改。
7. 人工把关：最终报价、法务结论、验收结论、银行账户、公章签字、正式导出和对外发送必须确认。
8. 可追溯：每个关键字段保留来源文件、页码或单元格、确认人、时间和版本。
9. 原件不覆盖：原始文件、历史版本和已确认版本不可静默覆盖或删除。
10. 真实交付：完成标准是可编辑 DOCX/XLSX 和可验证的 PDF 预览，不是 AI 返回一段文本。

## 3. 产品形态

### 3.1 主界面

- 左侧：项目工作区、对话、置顶、重命名、归档、删除。
- 中间：主聊天、自动增高输入框、附件卡片、任务进度和结果卡片。
- 输入区：添加文件、添加文件夹、粘贴截图、资料范围、联网范围和模型选择。
- 右侧抽屉：缺失资料、字段冲突、匹配模板、法务风险、预览、审批和版本。
- 左下角：账号、设置、更新、退出登录。

### 3.2 账号体验

- 支持记住账号和密码。
- 密码输入支持显示/隐藏。
- 支持退出登录。
- 管理员可以新增、停用和删除账号，配置共享案例和敏感资料权限。

### 3.3 工作区体验

- 用户可以绑定一个本地文件夹作为项目工作区。
- 工作区默认只读源文件，只向指定输出目录写入。
- 删除、覆盖、对外发送和 R2 上传需要相应权限。
- 用户可以直接说“整理这个文件夹”“生成报价”“做本次验收”。

## 4. 总体架构

```text
React Codex 式界面
        ↓
任务编排与工具调用层
        ↓
报价 / 合同法务 / 验收 / 结算 / 案例归档领域层
        ↓
确定性计算引擎 + 文档引擎 + 校验引擎
        ↓
SQLite 项目主数据 + Local Vault + 本地授权文件夹
        ↓
可选 AI API / R2 共享案例 / 联网网页搜索
```

### 4.1 保留的旧系统底座

- Tauri/Rust 桌面框架。
- React、TypeScript 和现有 SDK/HostAdapter/IPC 边界。
- SQLite、本地 Vault、资产完整性和 SHA-256。
- 文件导入、PDF 文本提取和 Windows OCR。
- 登录、管理员账号、记住账号能力。
- 模型和 API 配置。
- 任务引擎、事件、重试和审计记录。
- 合同审查、案例库和记忆服务的可复用部分。
- R2 上传、下载、校验、恢复和更新发布链路。

### 4.2 新建的业务层

- 新 Codex 式业务主界面。
- 新工作区和独立业务任务模型。
- 公司、客户项目、模板、报价、验收、年框和结算领域模型。
- 真实 DOCX/XLSX 文档引擎。
- R2 共享成果目录、增量索引、权限和去重规则。
- 联网搜索、网页读取和来源记录工具。

## 5. 核心数据对象

1. Company：公司主体、工商、税务、银行、营业执照和敏感资料权限。
2. CustomerGroup：客户集团。
3. CustomerProject：具体客户项目。
4. Contract：单次合同或年框合同。
5. ContractVersion：合同、补充协议和法律审查版本。
6. ServiceOrder：年框下的服务订单或执行批次。
7. Quotation：报价版本。
8. QuotationItem：服务行项、价格、税率、数量、优惠和成本。
9. Deliverable：交付项及证明材料。
10. AcceptanceBatch：验收批次。
11. SettlementBatch：结算批次。
12. Invoice/Payment：发票、请款和回款。
13. TemplateVersion：客户项目、文档类型和生效日期对应的模板版本。
14. SharedCase：经确认并授权共享的成功案例。
15. GeneratedDocument/DocumentVersion：生成文档及版本。
16. ReviewTask/AuditLog：人工确认、权限决策和操作审计。

## 6. 公司和客户项目资料库

### 6.1 公司资料库

初始支持华邦、华晨、红枫、半山，并允许管理员后续手动新增、修改、停用和导入其他公司。

公司资料至少包括全称、简称、统一社会信用代码、地址、电话、法定代表人、开票信息、默认税率、多个收款账户、联行号、营业执照和有效期。

银行账号、公章等敏感资料区分发现、预览、引用、下载、修改和导出权限。普通商务可以被允许引用字段生成文件，但不一定能查看完整值。

### 6.2 客户项目库

层级固定为：客户集团 → 具体项目 → 文档类型 → 模板版本。

同一客户集团下不同项目可以继承通用规则，但不能默认使用完全相同的模板。每个具体项目保存联系人、甲方主体、合同、历史报价、历史验收、客户特殊措辞、签字盖章要求和最近成功模板。

## 7. 模板和成功案例体系

模板不训练成每客户一个技能。系统采用“通用业务技能 + 模板库 + 历史成功件索引”。

模板库包含：

- 客户提供的空白模板。
- 客户已经接受的历史成功件。
- 字段映射、循环表格、图片位置、分页规则、附件规则、签字盖章位和固定措辞。
- 模板版本、生效日期、停用状态和最近成功使用记录。

文档引擎支持四种模板：

1. 固定字段模板。
2. 循环表格模板。
3. 图文分页模板。
4. 正文与附件组装模板。

匹配优先级：用户明确选择 → 当前项目最近成功模板 → 当前项目同类型模板 → 同客户集团相似项目 → 通用模板。近似匹配不得静默生成正式版。

## 8. 独立报价场景

报价任务可以从聊天直接启动，不要求先完成 Brief、合同或验收。

输入来源包括用户描述、旧 Brief、客户模板、历史报价、服务库和共享成功案例。

系统负责：

- 服务行项建议和说明润色。
- 不含税价、含税价、税额、数量、小计、合计和大写金额计算。
- 原价、项目优惠额和优惠后合同价分层保存。
- 客户版、内部成本版、历史版本和审批状态。
- 毛利和超权限优惠预警。
- 输出真实可编辑 DOCX/XLSX 和 PDF 预览。

白鹅潭基准案例必须正确表现：21,200 × 4 = 84,800，项目优惠 4,900，最终合同价 79,900，不能修改单价凑出最终金额。

## 9. 独立验收场景

验收任务可以从合同、服务订单、历史成功件和本次素材直接启动，不要求报价必须由本系统生成。

系统负责：

- 识别本次验收批次和合同交付范围。
- 分类脚本、视频、截图、花絮、发布数据、发票和证明材料。
- 将素材映射到交付项。
- 在生成前列出缺失、冲突和重复材料。
- 根据客户项目配置生成需要的文件。
- 保留原始模板版式、表格、工作表、公式、填报说明和盖章位置。
- 进行合同号、公司主体、数量、单价、税率、优惠、金额、时长、发票和证明材料的一致性校验。

白鹅潭基准案例为 6 类文档内容、5 个交付文件。当前素材只有 3 组而合同要求 4 条时，必须阻止正式版并提示缺 1 条。

## 10. 年框和复用

系统同时支持单次项目和年框项目。

```text
年框合同 → 服务订单/执行批次 → 验收批次 → 结算批次 → 发票 → 回款
```

支持季度、月度、按单、一次性和混合结算。每个交付项记录合同数量、累计执行、本期执行、累计验收、本期验收、累计结算、本期结算和剩余数量。

同一交付项不得被两个结算批次重复引用。价格表、合同和模板带版本与生效日期。年框主合同完整审查一次，后续只审查补充协议和发生变化的条款。

## 11. 记忆与 R2 共享成果库

产品是个人本地优先版本，不建设所有人实时协作的中央业务数据库。

信息分为：

1. 个人聊天和草稿：仅本地。
2. 当前项目资料：本地工作区。
3. 已确认成果案例：按权限进入 R2。
4. 公司基础知识：管理员发布到 R2。

R2 保存原文件和不可变案例清单。每台电脑同步被授权的目录清单，在本地建立结构化、全文和语义索引。

上传前计算 SHA-256。完全相同文件只保存一个物理对象；不同项目可以建立独立逻辑引用。文件内容不同但合同编号和项目相同，识别为可能的新版本。相似文件只提示，不自动删除。

## 12. 管理员权限

默认不允许跨用户检索。

管理员按用户、角色、客户、项目、文档类型和单个案例控制：

- 发现：是否能在搜索结果看到标题和摘要。
- 预览：是否能查看脱敏内容。
- 引用：AI 是否可以将案例用于当前任务。
- 下载：是否能下载原始文件。
- 发布：是否能提交共享案例。
- 修改：是否能修改共享标签和配置。
- 删除：是否能停用或撤回案例。
- 导出：是否能将敏感资料带出软件。

AI 只能检索被授权并同步到当前用户索引的数据。关闭跨用户检索后，不向该用户同步其他人的标题、摘要、文本或向量。

## 13. 联网搜索

聊天输入区提供：仅本地、本地 + 共享案例、允许联网。

联网模式支持搜索公开网页、打开网页、读取内容、下载公开附件、保存来源和访问日期。优先使用官方和一手来源。外部结果先标记为未确认资料，不得直接覆盖正式公司、合同或项目数据。

涉及客户秘密时，不把合同原文、银行账号和其他敏感信息发送到公共搜索引擎。

## 14. 自动化边界

### 14.1 全自动

- 文件扫描、分类、字段提取和查重。
- 金额、税额、大写金额、数量和表格计算。
- 素材匹配、表格扩行、图文分页和文件命名。
- 版本保存、来源记录和一致性校验。
- 已授权类型的 R2 归档和索引同步。

### 14.2 半自动

- 首次模板配置和字段纠错。
- 服务行项选择和项目优惠。
- 合同风险处置。
- 素材与交付项映射。
- 共享案例归档范围。

### 14.3 必须人工确认

- 最终报价。
- 最终合同和法务风险。
- 验收和结算结论。
- 收付款、银行、公章和签字信息。
- 正式导出、对外发送、覆盖和删除。

## 15. 业务版 1.0 范围

1.0 必须包含：

- Codex 式聊天、文件和文件夹工作区。
- 账号、记住密码、显示密码、退出登录和管理员权限。
- 独立报价和独立验收。
- 公司、客户项目、单次合同、年框、服务订单和批次。
- 模板库、报价案例库和验收成功件库。
- 真实 DOCX/XLSX、PDF 预览、图文分页和附件拼接。
- 确定性计算和跨文档校验。
- R2 共享成果、SHA-256 去重、本地索引和管理员授权。
- 基础合同填充、法务风险清单和建议条款。
- 可选联网搜索和来源记录。
- Windows/macOS 打包、升级、备份和回滚。

1.0 暂不包含：

- 视频自动抽帧和自动选图。
- 企业微信、邮件、电子签章和复杂多级审批。
- 完全离线的本地大模型。
- 任意控制整台电脑。
- 无需人工配置即可理解全部客户模板。
- 多人实时编辑同一份业务数据。

## 16. 开发策略

采用“新业务壳 + 复用成熟底层”，不原地重构全部旧页面，也不重写全部底层。

停止继续扩展旧 App、BusinessDocumentsCenter、BusinessWorkbench 和提示词智能体页面。新 1.0 建立独立主入口和领域模块；旧页面先作为兼容入口保留，旧数据通过迁移和适配读取。

数据库只做向前迁移。每次迁移前备份，禁止静默删除旧表和历史文件。

## 18. 1.0 验收标准

1. 两台不同 Windows 电脑连续冷启动 20 次不闪退，macOS 完成启动和基础任务烟测。
2. 报价可以独立启动，金额、优惠、税率和版本正确，输出可编辑文件。
3. 验收可以在没有本系统报价的情况下从合同和素材直接启动。
4. 白鹅潭缺 1 组素材时阻止正式版；补齐后生成 5 个文件、6 类内容。
5. 年框连续运行两个季度和一次单独结算，不重复引用已结算交付项。
6. A 发布案例后，只有管理员授权的 B 可以发现、引用或下载。
7. 重复文件不重复上传，新版本不被误删，离线任务联网后继续同步。
8. DOCX 逐页预览无明显错位；XLSX 保留工作表、公式、填报说明和盖章位置。
9. 所有金额和关键字段能追溯到来源、确认人和版本。
10. 所有自动化任务失败后可重试，不破坏原始文件和已确认版本。

## 19. 发布和安全要求

- GitHub 只保存源码和无密钥示例配置。
- R2、AI 和发布凭据通过本地私密配置或 GitHub Secrets 注入。
- 带 KEY 的内部安装包只上传到受控 R2 路径，不提交 Git。
- 每次发布保存安装包、源码快照、SHA-256、版本说明和构建日志。
- 安装包未购买代码签名证书前，明确标记为内部未签名版本。
- 已经进入 Git 历史的旧密钥必须轮换，不能只删除当前文件。
